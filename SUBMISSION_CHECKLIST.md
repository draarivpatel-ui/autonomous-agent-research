# Submission checklist

## Technical evidence

- Rerun the exact benchmark scripts and preserve their raw ledgers.
- Validate every notebook by execution, not only by JSON syntax.
- Keep source hashes, corpus license and dependency lock with the paper.
- Keep simulated channels and actual hardware results labelled separately.
- Disclose AI assistance, generated fixtures and unexecuted model or hardware paths.

## Entry evidence

- Read the specific venue's full current eligibility, originality and AI clauses.
- Verify every required model, SDK and target-hardware integration.
- Establish legitimate entrant eligibility without changing identity or work history.
- Record actual Kiro usage if the venue requires it.
- Use a new compliant demo, not legacy footage showing old claims.
- Submit no private profile, address or named institution through public code or prose.

## Publication

- Confirm the authenticated GitHub account and exact repository owner.
- Use the public noreply commit identity required by the station.
- Include all and only reviewed task changes.
- Preserve unrelated user files and do not rewrite old history without explicit authority.
- Treat the Kaggle metadata files as templates until real dataset and account identifiers are supplied.
